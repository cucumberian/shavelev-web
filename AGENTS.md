## Решённое — не «чинить» (10.10.2026)
Метка блока потерь печатается как «H = i·L·(1+k) = …» и при k = 0 (когда местные отключены).
Оригинал в этих случаях печатает «H = i·L= …». Решение человека 10.10.2026: расхождение косметическое,
правка задела бы формат вывода и ожидания тестов — оставляем как есть, не переделывать.

## Архитектура: материал = данные + поведение (рефакторинг 13.10.2026)

Знание о странице труб лежит в **одном месте — модуле материала**. Раньше оно было размазано по трём
слоям, и одна и та же форма данных опознавалась в UI четыре раза (`fillDiameters`, `curDv`, `dpOf`,
`applyClsState`); две копии правила «как считать dв» разошлись на пороге 300 мм у чугуна (v0.2.2).

```
js/fmt.js       печать чисел (fmt/fmt2/fmt3/vbs) — ПЕРВЫЙ <script>
js/formulas.js  формулы и константы EXE
js/data/*.js    ДАННЫЕ + ПОВЕДЕНИЕ страницы: MATERIAL_X.page = {…}   ← всё знание о материале
js/calc.js      расчётный движок: validate → compute → строки вывода
js/ui.js        DOM-адаптер: pageState() → page.* → вывод (знаний о материалах не содержит)
js/help/*.js    справка: по файлу на страницу, читает тот же движок
```

### `m.page` — контракт страницы (все функции ЧИСТЫЕ: без DOM)

| ключ | смысл |
|---|---|
| `blocks` | какие блоки-селекторы страница показывает (`clsRow`, `vtRow`, `peRow`, `pnRow`, …) |
| `labels` | подписи строк `d` / `t` / `dv` |
| `otherCap` | подпись флажка «другой» (у пластика — «не по ГОСТу») |
| `rows(st)` | строки списка диаметров `[[значение, подпись], …]` |
| `wallRows(st,d)` | стенки для выбранного диаметра (нет поля — не задано) |
| **`dvOf(st,d)`** | ★ **закон расчётного диаметра — единственный в проекте** |
| `rec` | правило строки рекомендации (`rec.mode:'vel'|'ranges'`) |
| `gated` | гасит ли «другой» выбор по списку |
| `hideDsel`, `keepNearest` | частности ПЭ 100 (список скрыт; при смене серии — ближайший dн) |
| `recKey` / `rowValue` | перевод dу ↔ dн (только сталь: ряд рекомендации задан в dу, а #dsel хранит dн) |
| `mestLimit(st,d)` | порог блока местных сопротивлений (только две стальные страницы) |
| `duLine`, `ciDims` | тексты строк под селектором (сталь, чугун) |
| `pnList`, `table` | кнопки PN и таблица размеров ПЭ 100 |
| `pickSeries`, `seriesEnabled`, `peOrder` | переключатель серий ПЭ (порядок серий В ОКНЕ программы) |
| `hiddenVt` | класс, который при типе прячется целиком (а/ц: ВТ15 при типе 1) |

**СП-семейство** (`page.kind:'sp'`) — страницы, считающие по λ и с редактором ξ: медь, PEX,
PEX-AL-PEX. Движок их **не различает по имени**: он видит признак `kind` и берёт оттуда всё.

| ключ | смысл |
|---|---|
| `sys` | карта систем Frame2: `{cold, hot/circ/supply, heat → {cap, lim, note, cold?, t?, heat?, formula?, nu?}}`. Признаки: `cold` — блоки «Температура»/«Теплоноситель» неактивны, ν и ρ фиксированы; `t` — температура обязательна; `heat` — системы отопления; `formula:3` — брать формулу (3) вместо (2); `nu` — вязкость, не зависящая от t (медь, циркуляционное ГВС: 0,36·10⁻⁶) |
| `loss(S,nu,v,d,rho,sp)` | формула страницы → `{i, R}`. У меди три ветки СП 40-108-2004, у PEX одна λ на все системы |
| `fluid(S,t)` | ν и ρ для теплоносителя «вода» по температуре; `null` — строки нет (t<50), берутся умолчания программы |
| `xi` | список местных сопротивлений [[подпись, ξ], …] |
| `out` | подписи вывода: `iWith1000`, `rHeat(R)`, `dP(P)`, `dPHeat(P)`, `drop(P)` — тексты шаблона формы EXE; у меди и PEX они разные |
| `seriesRow(d)` | строка сортамента ПЭ [S, ΔS, Δd] (читает справка) |

Добавление четвёртой такой страницы = один модуль `js/data/*.js`; ни `js/calc.js`, ни `js/ui.js`
не меняются. Проверка — `test/page_test.js`.

`st` — состояние страницы, собирает `pageState()` в `ui.js`: `{cls, vt, tip, pe, sdr, sdr100, series,
S, wear}`. Оно — единственный мост между DOM и чистыми функциями материала.

### Что дало

- **Закон `dв` написан один раз** вместо двух копий (`curDv` + `dpOf`); класс баг, породивший
  историю с порогом 300 мм, закрыт конструктивно.
- `fillDiameters()` — 90 строк лестницы `if/else if` → 25 строк общего кода; `ui.js` 811 → 590 строк.
- `calc.js`: медная и PEX-ветки были двумя копиями по ~90 строк → один `spCalc`; проверка ввода
  была продублирована трижды → одна `validate()` с двумя наборами текстов (тексты EXE у страниц разные).
- `calc.js` теперь читается как методика: единицы → скорость → уклон → R → H → ΔP → предупреждения.
- Медь, PEX и PEX-AL-PEX перестали быть особняком: `copperCalc`/`pexCalc` и `applyCopperVisibility`/
  `cuSysSync`/`cuHeatSync`/`T_NU_RHO`/`pexRow` удалены, всё описано в `page` их модулей. В `js/ui.js`
  не осталось ни одного имени материала, в `js/calc.js` — только резервные списки `NO_SYS`/`NO_WEAR`,
  которые нужны как эталон `calc_test.js`.
- Рекомендация: три алгоритма + два частных случая по `m.id` → один алгоритм, правило в `page.rec`.
- `test/page_test.js` — 121 проверка чистых функций страниц **без jsdom** (было невозможно).

### Правила при правке

- Функция в `m.page` **не имеет права** трогать DOM и читать контролы — иначе её нельзя проверить
  в node. Тексты и числа от страницы возвращаются данными, рисует `ui.js`.
- Подписи строк набираются **латиницей `d`** («`dн=88,5 мм`», «`dу=100 мм`», «`dв=500 мм`») — так их
  печатает программа. Кириллическая `д` в подписи — ошибка, её ловят тесты UI.
- Числовые ключи объектов (`'6'`, `'9'`, `'21'`) JS переставляет в начало в порядке возрастания —
  «первый» элемент `Object.keys` не значит «первый в окне». Порядок, важный для выбора, задаётся
  явно (`page.peOrder`).
- `js/data/*.js` подключаются **до** `calc.js`, поэтому `fmt()` для них живёт в отдельном `js/fmt.js`;
  в node `js/data/index.js` подставляет его глобалы сам.

## Структура и модульность (не нарушать)
- `index.html` — только разметка; `styles.css` — все стили (никаких inline-стилей контролов);
- `js/formulas.js` — формулы (при изменении — комментарий с формулой и ссылкой на корневой `../AGENTS.md`);
- `js/fmt.js` — печать чисел; `js/data/` — справочники, **по одному модулю на тип труб**
 (`steel.js`, `steel-es.js`, `ci.js`, `asbes.js`, `plastic.js`, `conc.js`, `grp.js`, `glass.js`,
 `copper.js`, `pex.js`, `metal-pex.js`, `pe100.js`), каждый со своим `page`; общий реестр материалов —
 `js/data/registry.js` (`registerMaterial` → `MATERIALS`); общие таблицы —
 `js/data/docs.js` (подписи ГОСТ/СП) и `js/data/modes.js` (`VEL_LIMIT/K_MODE/MODE_SYS/VREC`);
 `js/data/index.js` — сборка для node-тестов. Источник значений — EXE-реверс, не выдумывать;
- `js/calc.js` — **расчётный движок**: единицы расхода, v, i, R, H, предупреждения по скорости,
 строка рекомендации, печать чисел (fmt/fmt2 в `js/fmt.js`). Только вычисления, DOM не трогает —
 правки формул и проверка логики делаются здесь и тестируются `test/calc_test.js` без jsdom;
- `js/ui.js` — разметка DOM: чтение контролов (`readForm`, `pageState`), вызов движка, вывод, справка;
 `js/webmcp.js` — WebMCP-инструменты (регистрация после ui.js), тот же движок.
- **Карта видимости блоков** живёт декларативно в данных страниц: `m.ui{sys,wear,cu}` — есть ли в
 оригинальном окне стальной блок «Режим / теплоноситель», «новые/неновые», свои рамки медь/PEX;
 читает движок (`js/calc.js` → `usesSys/usesWear/usesCu/usesK`). Что показывать внутри страницы —
 объявляет `m.page.blocks`. `NO_SYS`/`NO_WEAR` остались резервом для страниц без карты и эталоном
 для `test/calc_test.js`.
- **Один вход для расчёта**: `readForm()` (`js/ui.js`) собирает объект входа движка в одном месте —
 `calc()` берёт его оттуда. Подстановка чисел в справку (`js/help/<id>.js`) читает те же контролы и
 зовёт тот же `shevCalc` — потому числа справки равны выводу страницы. `readForm()` делегирует в
 `curDv()`, `cuSysVal()`, `xiTotal()`, `cuCool()`, а `calc()` дополнительно строит `dpOf` —
 осознанно зависимые читатели; `dpOf` больше не дублирует закон, а зовёт `m.page.dvOf`.
- **Никаких скрытых цепочек обработчиков**: вместо вызова чужого обработчика (`$('mode').onchange()`)
 — именованная функция (`syncK()`, `syncSteelT()`), которую обработчики зовут явно.
- **Блок местных сопротивлений на стальных страницах гасится по диаметру, а не по системе** (12.10.2026,
 живая сверка с оригиналом): строка «учесть потери на местные сопротивления», «Режим» и `k` **исчезают**
 — в рамке «Потери напора на участке, м» остаётся только «Длина участка L=» — одинаково в ХВС и ГВС.
 Порог разный на двух страницах и задаётся данными: сталь ВГП — **dу ≥ 80 (dн ≥ 88,5)**,
 электросварные — **dн ≥ 88**. Порогом управляет `page.mestLimit`, его зовёт `applyMestLimit()`.
 Подпись рамки не переименовывается. k задаётся режимом (`K_MODE`), ручного поля k в оригинале нет.
- **Галочка «учесть потери на местные сопротивления» по умолчанию СНЯТА** — при смене системы её
 состояние сохраняется. `sysCold`/`sysHot` её не поднимают — только пересобирают список режимов и
 зовут `applyMestLimit()`.
- Файлы подключаются обычными `<script>` в порядке: **fmt** → formulas → data/registry → data/docs →
 data/modes → модули труб (порядок вкладок: steel, steel-es, ci, asbes, plastic, conc, grp, glass,
 copper, pex, metal-pex, pe100) → calc → ui → webmcp. Не переводить в ES-модули: клон обязан
 открываться двойным кликом с `file://`.
- Верхние `const` модулей труб попадают в общую глобальную лексическую область: имена уникальны.
- Новая страница = новый файл `js/data/<тип>.js` (данные + `page`) + `<script src>` в index.html +
 файл справки `js/help/<тип>.js` + проверки в `test/page_test.js` и `test/ui/`. В `js/ui.js` и
 `js/calc.js` для неё дописывать нечего — кроме новой формулы в `js/formulas.js`.

## Тесты — обязательны перед любым коммитом
- **TDD: тест фиксирует ПРАВИЛЬНОЕ (оракульное) поведение.** Ошибочное поведение в тестах оставлять
 нельзя: если нашлась причина расхождения (ошибка формулы, неверные данные) — тест в тот же момент
 переписывается на оракульные значения, а не подгоняется под текущий (неверный) код.
- `cd shevelev-web/test && node run_all.js` — один вход для всех проверок, код возврата 1 при падении:
 движок `test.js`, эталоны `calc_test.js`, **страницы `page_test.js` (законы dв, списки, рекомендация
 — без jsdom)**, UI `ui_test.js`, крайние случаи `edge_test.js`, WebMCP `webmcp_test.js`,
 E2E в headless Chrome `e2e/browser_run.js` (таблица точек — `e2e/oracle.js`),
 сверка справки с движком `help_check.js`. Любая правка формулы в `js/formulas.js`/`js/calc.js`
 обязана проходить `run_all.js` целиком.
- Наборы по отдельности: `node test.js && node calc_test.js && node page_test.js && node ui_test.js
 && node edge_test.js && node webmcp_test.js`. Счётчики — в выводе `run_all.js`; он и есть источник истины.
- Быстрые проверки вёрстки в реальном браузере: headless Chromium (`--headless=new --screenshot`,
 iframe-пробы переполнения через `--dump-dom` + `document.title`).

## Прочее
- **Неактивные контролы — одно глобальное правило в styles.css** (`input/select/textarea:disabled` → цвета `--off-bg/--off-fg/--off-border` из `:root`): гасится ТОЛЬКО само поле, подпись (заголовок) остаётся обычной. Целые блоки гасятся классами `.off` (медь: Frame4 «Температура», Frame5 «Теплоноситель») и `.locked` (страницы с фиксированными ν/ρ/k) — там блекнут легенда и подписи, как в оригинальном окне.
- **Глобальная версия и футер** — не относятся ни к одной вкладке: версия клона (= последний git-тег,
 без слова «клон») стоит **в хэдере справа мелким шрифтом** (`<span class="ver">` в `<h1>`, `h1 .ver` в styles.css);
 `.footnote` печатает «Санкт-Петербург, 2026» + иконка-ссылка на репозиторий (версии там нет).
 Тесты — в `test/ui/05-global.js` (общие элементы страницы), а не в секции материалов.
- Мобильная вёрстка: брейкпоинты 820px (колонки) и 480px (телефон); контролы ≥16px шрифта (анти-зум iOS).
- Формулы и данные — только из реверса EXE (или книги Шевелевых, если EXE молчит); как именно они получены —
 в корневом `../AGENTS.md`.
